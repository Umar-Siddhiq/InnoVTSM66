# OVERVIEW

COLORPLAST SIM is a multi-profile SIM.

The SIM internally contains multiple operator profiles:

```
Profile 1 -> Airtel
Profile 2 -> BSNL
Profile 3 -> Vi
```

Only one profile can be active at a time.

The firmware uses STK (SIM Toolkit) commands to:
1. Initialize STK session
2. Navigate SIM internal menu state
3. Select required profile
4. Confirm selection
5. Reset modem
6. Verify IMSI changed

---

#define STK_COLORPLAST_SETUP_COUNT        2
#define STK_COLORPLAST_PROFILE_COUNT      3

#define STK_COLORPLAST_MENU
"810301250082028281830100"

#define STK_COLORPLAST_ITEM

## CONFIRMATION COMMAND:

---

# MEANING OF type FIELD

type decides WHICH API should send the STK packet.

There are TWO STK communication methods.

---

# TYPE = 0

type = 0 means:

```
Use:
RIL_QSTKTerminalResponse()
```

Meaning:
This packet is treated as a TERMINAL RESPONSE.

This is used when modem/phone is RESPONDING to SIM.

Examples:
- menu response
- confirmation response
- selection response

---

# TYPE = 1

type = 1 means:

```
Use:
RIL_QSTKEnvelopeCommand()
```

Meaning:
This packet is treated as an ENVELOPE COMMAND.

This is used when modem/phone is SENDING EVENT OR USER ACTION to SIM.

Examples:
- key press
- menu navigation
- event notification
- selection event

---

# WHY type IS IMPORTANT

SIM Toolkit protocol expects packets in proper format and direction.

If wrong API is used:

```
- SIM ignores command
- STK session breaks
- menu state becomes invalid
- profile switch fails
```

Therefore:

```
type = 0 -> TerminalResponse()
type = 1 -> EnvelopeCommand()
```

is VERY IMPORTANT.

# WHAT THIS COMMAND DOES

This is the FIRST STK initialization/menu command.

This packet initializes STK interaction state.

SIM internally interprets this as:

```
Terminal response for menu/session setup.
```

This packet is NOT treated as:
- user event
- key press

Therefore:
TerminalResponse() is correct API.

If success:

Firmware waits 1.5 seconds.

Reason:
SIM needs time to process STK packet and update internal menu/session state.

Now I'll provide a comprehensive explanation of how `GetNextValidProfile()` works with failure history tracking:

## **`GetNextValidProfile()` - Intelligent Profile Selection System**

### **Overview:**
This function intelligently rotates between available profiles, **automatically skipping broken ones** based on failure history. It ensures the device keeps trying different carriers until it finds one that works.

---

### **Key Data Structure: Failure Tracking**

```c
// In VTS.h (line 556):
typedef struct {
    uint8_t CurrentProfile;        // Currently active profile (1-3 for IDEMIA_3P)
    uint8_t ProfileFailCount[5];   // Tracks consecutive failures per profile
                                   // Index 0: unused
                                   // Index 1-3: AIRTEL, BSNL, VIL (for IDEMIA_3P)
                                   // Index 4: reserved
} VTSStateTypedef;
```

**Failure Threshold:** `MAX_CONSECUTIVE_FAILS = 3`
- Once a profile fails 3 consecutive times, it's **skipped** automatically
- Only profiles with `ProfileFailCount < 3` are tried

---

### **How Failures Are Tracked:**

#### **Failure Case 1: IMSI Read Failed**
```c
// When profile switch command sent but IMSI check fails
if (ret != RIL_AT_SUCCESS)  // Failed to read new IMSI
{
    VTSState.ProfileFailCount[num]++;  // Increment failure count
    LOGData(..., "Profile %d switch failed (IMSI read error), fail count: %d", 
            num, VTSState.ProfileFailCount[num]);
}
```
Example:
- Try Profile 1 → IMSI read fails → `ProfileFailCount[1] = 1`
- Try Profile 1 again → IMSI read fails → `ProfileFailCount[1] = 2`
- Try Profile 1 again → IMSI read fails → `ProfileFailCount[1] = 3` ❌ **BLACKLISTED**

#### **Failure Case 2: Profile Doesn't Exist on SIM**
```c
// When IMSI didn't change (profile doesn't exist on this SIM)
if(Ql_strstr(imsi, NetWork.IMSI))  // Same IMSI = profile not found
{
    VTSState.ProfileFailCount[num]++;
    LOGData(..., "Profile %d switch failed (non-existent profile), fail count: %d");
}
```
Example: SIM only has profiles 1 & 3, but no profile 2
- Try Profile 2 → IMSI unchanged → `ProfileFailCount[2] = 1`
- Try Profile 2 → IMSI unchanged → `ProfileFailCount[2] = 2`
- Try Profile 2 → IMSI unchanged → `ProfileFailCount[2] = 3` ❌ **BLACKLISTED**

#### **Success: Reset Failure Count**
```c
// When profile successfully switches (IMSI changed)
LOGData(TAG_GPRS, "Profile Successfully Changed");
VTSState.ProfileFailCount[num] = 0;  // Reset to 0
LOGData(..., "Profile %d switch successful, resetting fail count", num);
```

---

### **Algorithm: GetNextValidProfile()**

```
START with nextProfile = (currentProfile % profiles_supported) + 1

LOOP through all available profiles:
    IF ProfileFailCount[nextProfile] < 3:
        ✅ Found valid profile! Return it
    ELSE:
        ⏭️ Try next profile (wrap around if needed)

IF ALL profiles have ≥ 3 failures:
    🔄 RESET all ProfileFailCount[i] = 0
    ↩️  Return profile 1 (fresh start)
```

---

### **Practical Example with IDEMIA_3P (3 Profiles)**

#### **Scenario: Airel (P1) is broken, BSNL (P2) works, VIL (P3) is broken**

**Initial State:**
```
CurrentProfile = 3 (VIL)
ProfileFailCount[1] = 0 (AIRTEL - not tried yet)
ProfileFailCount[2] = 0 (BSNL - not tried yet)
ProfileFailCount[3] = 0 (VIL - not tried yet)
```

**Timeout triggers at 2 minutes:**
1. `GetNextValidProfile(3)` called
2. Next = (3 % 3) + 1 = **1 (AIRTEL)**
3. Check: `ProfileFailCount[1]` (0) < 3? ✅ YES
4. **Return 1** → Try AIRTEL

**AIRTEL fails (network error):**
```
ProfileFailCount[1] = 1
```

**Timeout triggers at 4 minutes:**
1. `GetNextValidProfile(1)` called
2. Next = (1 % 3) + 1 = **2 (BSNL)**
3. Check: `ProfileFailCount[2]` (0) < 3? ✅ YES
4. **Return 2** → Try BSNL

**BSNL succeeds (IMSI changes):**
```
ProfileFailCount[2] = 0  (reset to 0)
CurrentProfile = 2      (now using BSNL)
```

**Later, BSNL loses signal (timeout 2 min):**
1. `GetNextValidProfile(2)` called
2. Next = (2 % 3) + 1 = **3 (VIL)**
3. Check: `ProfileFailCount[3]` (0) < 3? ✅ YES
4. **Return 3** → Try VIL

**VIL fails 3 times:**
```
ProfileFailCount[3] = 1, 2, 3 ❌ BLACKLISTED
```

**Next timeout at 8 minutes:**
1. `GetNextValidProfile(3)` called
2. Try profile 1: `ProfileFailCount[1]` (1) < 3? ✅ YES
3. **Return 1** → Try AIRTEL again

---

### **Smart Behavior Summary:**

| Situation | Behavior |
|-----------|----------|
| Profile works perfectly | Keep using it (fails = 0) |
| Profile fails once or twice | Try it again next rotation |
| Profile fails 3 times | **Skip it completely** |
| All profiles fail 3+ times | **Reset everything and start fresh** |
| Found good profile | Stay on it until it disconnects |

---

### **For Your IDEMIA_3P Setup:**
- ✅ **Profile 3 (AIRTEL):** Set as default - if it works, stays active
- ✅ **Profile 2 (BSNL):** Tried if Profile 3 fails 3 times
- ✅ **Profile 1 (VIL):** Tried if Profile 2 fails 3 times
- 🔄 **Auto-reset:** If all fail, counters reset and cycle restarts

This ensures **maximum uptime** by automatically avoiding bad profiles while regularly retrying them in case the network recovers.
